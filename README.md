# Транскрибатор видео для Telegram

Телеграм-бот: присылаете ссылку на YouTube, Instagram, VK или TikTok либо сам файл
(видео, аудио, голосовое, видеосообщение) — бот извлекает звуковую дорожку,
расшифровывает её через OpenAI Audio API и возвращает текст.

На ссылку бот сначала отвечает превью ролика с двумя кнопками — «Скачать видео»
и «Транскрибировать». Под готовой расшифровкой есть ещё три: краткий конспект,
вопросы по содержанию видео и интерактивный конспект с мини-тестом.

Что внутри:

- `yt-dlp` скачивает с площадки только аудио, `ffmpeg` жмёт его в mp3 16 кГц моно (64 кбит/с);
- YouTube, Instagram, VK и TikTok поддержаны одинаково: превью, скачивание, расшифровка, вопросы, тест;
- присланные в Telegram файлы проходят тот же путь: из видео извлекается звук, дальше всё одинаково;
- режим `/group` копит несколько записей и расшифровывает их в один файл;
- длинное аудио автоматически режется на части по 15 минут, чтобы влезать в лимит OpenAI 25 МБ,
  части расшифровываются параллельно;
- готовые расшифровки кэшируются в `data/transcripts`, повторный запрос того же видео бесплатен;
- очередь задач: одновременная обработка ограничена, у пользователя не больше 3 задач;
- доступ по списку Telegram ID (иначе за ваш ключ OpenAI будут платить незнакомцы);
- расшифровка до 3500 символов приходит сообщением, длиннее — файлом `.txt`;
- по кнопке под превью бот может отдать сам файл видео в mp4 (в пределах лимита Telegram);
- по расшифровке можно задавать вопросы и пройти автоматически собранный тест.

## Требования

- Python 3.10+
- ffmpeg и ffprobe в `PATH`
- [deno](https://deno.com/) в `PATH` — свежий yt-dlp исполняет JavaScript со страниц
  YouTube, без рантайма часть форматов недоступна (на Ubuntu ставится скриптом установки)
- токен бота от [@BotFather](https://t.me/BotFather)
- ключ [OpenAI API](https://platform.openai.com/api-keys) с положительным балансом

## Быстрый старт локально

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # впишите BOT_TOKEN и OPENAI_API_KEY
python -m app
```

Дальше в Telegram: `/start`, затем `/id` — полученный ID впишите в `ALLOWED_USER_IDS`
и перезапустите бота.

## Развёртывание на VPS с Ubuntu

Всё делается за пять команд от пользователя с sudo:

```bash
sudo apt update && sudo apt install -y git
sudo git clone <URL-вашего-репозитория> /opt/transcriber
cd /opt/transcriber
sudo bash deploy/install.sh        # пакеты, venv, systemd-юнит, автозапуск
sudo nano .env                     # BOT_TOKEN, OPENAI_API_KEY, ALLOWED_USER_IDS
sudo systemctl start transcriber-bot
```

Если репозитория нет, скопируйте папку проекта с локальной машины:

```bash
# из корня проекта на своей машине
scp -r . root@IP:/opt/transcriber
```

Скрипт `deploy/install.sh` ставит `python3-venv`, `ffmpeg` и `deno`, создаёт системного
пользователя `transcriber`, собирает виртуальное окружение и включает сервис
`transcriber-bot` в автозапуск.

Полезные команды:

```bash
sudo systemctl status transcriber-bot     # состояние
journalctl -u transcriber-bot -f          # живые логи
sudo systemctl restart transcriber-bot    # после правки .env
sudo bash deploy/update.sh                # git pull + обновление зависимостей + рестарт
```

Бот работает на long polling, поэтому открытые порты, домен и сертификаты не нужны —
достаточно исходящего доступа в интернет. Минимальной VPS (1 ядро, 1 ГБ RAM, 10 ГБ диска)
хватает: тяжёлые вычисления происходят на стороне OpenAI, локально нужен только ffmpeg.
Для 1 ГБ RAM полезно добавить swap:

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## Что бот делает со ссылкой

Бот понимает ссылки на **YouTube, Instagram, VK и TikTok** — все они идут через
`yt-dlp`, поэтому набор возможностей у них одинаковый. Распознаются основные формы
ссылок: `youtu.be/…` и `youtube.com/{watch,shorts,live,embed}`, `instagram.com/{p,reel,reels,tv}/…`,
`vk.com/video…`, `vk.com/clip…`, `vkvideo.ru/…`, `tiktok.com/@user/video/…` и короткие
`vm.tiktok.com/…`.

На ссылку бот отвечает не сразу задачей, а превью: обложка ролика, название, автор,
длительность и число просмотров — и две кнопки.

- **«Скачать видео»** — `yt-dlp` качает картинку со звуком и склеивает их в mp4,
  после чего бот присылает файл в чат. Под ним остаётся кнопка «Ещё и расшифровать»,
  чтобы не искать ссылку заново.
- **«Транскрибировать»** — привычный путь: скачивается только аудио, дальше
  расшифровка. У TikTok и Instagram отдельной аудиодорожки нет, поэтому качается
  готовый файл, а звук из него вырезает `ffmpeg` — снаружи разницы не видно.

### Как выбирается качество

Бот не качает вслепую: он сначала запрашивает список доступных дорожек, считает
их размер и берёт **лучшее качество, которое влезает в лимит отправки**, но не выше
`MAX_DOWNLOAD_HEIGHT`. Дорожки указываются явными id (`299+140`), а не расплывчатым
селектором, — иначе `yt-dlp` молча скатывается к неожиданному варианту.

Потолок считается по короткой стороне кадра, поэтому `1080` — это и горизонтальные
1920x1080, и вертикальные 1080x1920 (Shorts, Reels, TikTok). При равном качестве
предпочитается H.264: его Telegram играет прямо в чате на любом клиенте.

Если ролик целиком не помещается, бот берёт качество ниже и честно пишет об этом
в подписи: `🎚 480p (доступно 1080p, но не влезало в лимит) · 37 МБ`. Если не влезает
даже минимальное качество — отказывается и объясняет, почему.

**Про лимит.** Публичный Bot API разрешает боту отправить не больше 50 МБ. Для 1080p
это примерно две минуты видео — то есть полноценное 1080p на публичном API возможно
только для коротких роликов. Чтобы качать 1080p нормальной длины, поднимите
локальный Bot API сервер и укажите `TELEGRAM_API_URL`: лимит вырастет до 2000 МБ.

Скачанный файл перед отправкой проверяется через `ffprobe` — в нём обязаны быть
и видео, и звук. Это страховка от ошибки, которая была здесь до v0.5: любой ролик
тяжелее лимита обрывался на полуслове, склейка не происходила, и пользователю
уходил промежуточный файл — например, одна звуковая дорожка без картинки.

Разобранное превью держится в памяти процесса (последние 200 роликов), поэтому
нажатие кнопки не заставляет ходить на площадку второй раз. Сама ссылка при этом
кладётся в `data/links/` под коротким ключом: в `callback_data` Telegram влезает
только 64 байта, а ссылки VK и TikTok длиннее. Благодаря этому кнопки продолжают
работать и после перезапуска сервиса.

Расшифровки кэшируются по id ролика с префиксом площадки (`tt_…`, `vk_…`, `ig_…`):
id у разных площадок пересекаются, а у YouTube префикса намеренно нет, чтобы ранее
накопленный кэш остался валидным.

## Локальный Bot API сервер (необязательно)

**Бот работает без него.** Из коробки используется облачный Bot API: ничего, кроме
`BOT_TOKEN` и `OPENAI_API_KEY`, заполнять не нужно, `TELEGRAM_API_URL` можно оставить
пустым. Всё, что описано выше, работает — просто длинные ролики приезжают в пониженном
качестве, потому что в 50 МБ больше не влезает.

Локальный сервер нужен ровно для одного: поднять лимиты с 50/20 МБ до 2000 МБ, чтобы
скачивать длинное видео в 1080p. Это можно сделать когда угодно позже — переключение
не требует переустановки бота.

```bash
sudo bash deploy/install-bot-api.sh
```

Скрипт соберёт `telegram-bot-api` из исходников, заведёт systemd-юнит, разлогинит
бота из облака и пропишет `TELEGRAM_API_URL` в `.env`. Что нужно приготовить:

- **`api_id` и `api_hash`** с [my.telegram.org/apps](https://my.telegram.org/apps) —
  входить нужно обычным аккаунтом Telegram (не ботом), раздел «API development tools».
  Скрипт спросит их и положит в `/etc/telegram-bot-api.env` с правами `600`.
- **Место и время.** Сборка TDLib занимает от 10 минут до часа и требует около
  2.5 ГБ памяти. Если RAM с запасом не хватает, скрипт предложит создать swap.

Важные следствия, о которых стоит знать заранее:

- **Бот разлогинивается из облачного Bot API** (метод `logOut`) — без этого локальный
  сервер его не примет. После переключения бот работает только через локальный сервер.
  Вернуться назад можно, вызвав `logOut` уже у локального сервера:
  `curl "http://127.0.0.1:8081/bot<TOKEN>/logOut"`, затем очистить `TELEGRAM_API_URL`.
- **Порт слушается только на 127.0.0.1.** Наружу его выставлять нельзя: у сервера нет
  своей авторизации, доступ к порту равен полному управлению ботом.
- **Скачанные файлы копятся.** В режиме `--local` сервер складывает их в
  `/var/lib/telegram-bot-api` и сам не удаляет. Чистка раз в сутки:

```bash
echo '0 4 * * * root find /var/lib/telegram-bot-api -type f -mtime +1 -delete' \
  | sudo tee /etc/cron.d/telegram-bot-api-cleanup
```

После установки `MAX_FILE_MB` и `MAX_UPLOAD_MB` сами становятся равными 2000 —
отдельно их выставлять не нужно.

## Вопросы по видео

Под расшифровкой есть кнопка «❓ Вопрос по видео». По нажатию бот переходит в режим
вопросов: следующее сообщение он считает вопросом и отвечает по тексту расшифровки,
а не по своим общим знаниям — если ответа в видео нет, так и говорит.

Вопросов можно задать сколько угодно подряд. Выход — кнопка «Хватит вопросов»,
команда `/cancel`, новая ссылка или новый файл. Расшифровки длиннее 100 000 символов
разбиваются на части: вопрос задаётся к каждой, потом ответы сводятся в один.

## Интерактивный конспект с тестом

Кнопка «🧩 Интерактивный конспект + тест» отправляет расшифровку в chat-модель,
которая возвращает JSON: 3–5 разделов по логике видео и 5 вопросов с четырьмя
вариантами ответа. Результат кэшируется рядом с расшифровкой в
`data/transcripts/<токен>.lesson.json`, так что повторное открытие бесплатно.

Конспект листается кнопками «Назад» / «Вперёд» внутри одного сообщения. Кнопка
«Пройти тест» запускает опрос: на каждый вопрос показываются варианты A–D, после
ответа сообщение перерисовывается с отметками ✅/❌, пояснением и текущим счётом.
В конце — результат с процентом и полосой прогресса, рядом кнопки «Пройти заново»
и «Вернуться к конспекту».

Состояние теста (номер вопроса и счёт) целиком лежит в `callback_data` кнопок,
поэтому тест не занимает память и переживает перезапуск сервиса — в отличие от
режима `/group`.

Расшифровку длиннее 40 000 символов бот сначала сжимает обычным конспектом, иначе
тест собрался бы только по началу видео.

## Режим группы

Команда `/group` включает сбор записей. Дальше можно диктовать голосовые одно за
другим: каждое бот отмечает реакцией, но кнопку не показывает, пока вы не сделаете
паузу в `GROUP_DEBOUNCE_SECONDS` секунд — иначе на каждое сообщение появлялась бы
своя кнопка. После паузы приходит одна панель: «Собрано записей: N · общая
длительность» с кнопками «Расшифровать в единый файл» и «Отмена».

Если после появления панели прислать ещё запись, старая панель удаляется и
показывается новая с обновлённым счётчиком — кнопка всегда остаётся последним
сообщением в чате. Пауза отсчитывается заново.

По нажатию все записи скачиваются, расшифровываются одним пакетом (части всех
записей идут в OpenAI параллельно, как у одного длинного видео) и склеиваются в
один текст с заголовками вида `[Запись 3 · 1:12]`. Результат всегда приходит
файлом `.txt`, под ним — те же кнопки, что и под обычной расшифровкой: конспект,
вопросы и тест построятся уже по всей группе. После запуска режим выключается: чтобы собрать следующую группу,
отправьте `/group` заново, а `/cancel` выходит из режима и забывает собранное.

Ограничения режима: собранное живёт в памяти процесса, поэтому после перезапуска
сервиса кнопка ответит, что группа устарела; суммарная длительность проверяется
тем же лимитом `MAX_VIDEO_MINUTES`.

## Файлы, присланные в Telegram

Бот принимает видео, аудио, голосовые и видеосообщения, а также документы с
видео/аудио внутри — тип определяется по MIME или расширению. Длительность у
документов Telegram не сообщает, поэтому лимит `MAX_VIDEO_MINUTES` для них
проверяется после извлечения звука, но всегда до обращения к OpenAI, так что
слишком длинный файл денег не потратит.

Главное ограничение: **официальный Bot API не отдаёт боту файлы больше 20 МБ**
(это ограничение Telegram, а не бота). Для типичного видео это пара минут.
Варианты обхода:

1. Загрузить видео на YouTube и прислать ссылку.
2. Поднять [локальный telegram-bot-api](https://github.com/tdlib/telegram-bot-api)
   — тогда лимит поднимется до 2 ГБ. Проще всего в Docker (нужны `api_id` и
   `api_hash` с [my.telegram.org](https://my.telegram.org/apps)):

```bash
docker run -d --name telegram-bot-api --restart unless-stopped \
  -p 8081:8081 -v /opt/transcriber/data/tgapi:/var/lib/telegram-bot-api \
  -e TELEGRAM_API_ID=<api_id> -e TELEGRAM_API_HASH=<api_hash> \
  -e TELEGRAM_LOCAL=1 aiogram/telegram-bot-api:latest
```

Затем в `.env`: `TELEGRAM_API_URL=http://localhost:8081`. В локальном режиме
сервер не отдаёт файлы по HTTP, а кладёт их на диск, и бот читает их напрямую —
поэтому каталог с файлами должен быть доступен пользователю `transcriber` на
чтение, а сам сервис бота должен иметь его в `ReadWritePaths` юнита, если каталог
лежит вне `data`. Учтите: локальный сервер работает со своей сессией бота,
поэтому после переключения запустите бота один раз с тем же токеном и не
смешивайте два режима одновременно.

## Площадка не отдаёт видео анонимно

Самая частая проблема на VPS: с IP дата-центра площадка требует авторизацию.
У YouTube это `Sign in to confirm you're not a bot`, у Instagram и VK —
«отдаёт это видео только авторизованным». Варианты решения:

1. **Cookies.** В браузере, где вы залогинены на нужной площадке, экспортируйте
   cookies в формате Netscape (расширение вроде «Get cookies.txt») и укажите путь:
   `INSTAGRAM_COOKIES_FILE=/opt/transcriber/instagram.txt`. Один файл может
   содержать cookies сразу нескольких доменов — тогда достаточно `COOKIES_FILE`.
   Файлы держите в режиме `chmod 600`: это доступ к вашим аккаунтам. Желательно
   заводить отдельные аккаунты — за автоматизацию их могут заблокировать.
2. **Прокси.** Жилой или мобильный прокси в `YT_PROXY=http://user:pass@host:port`.
   Применяется ко всем площадкам сразу.
3. **Свежий yt-dlp.** `sudo bash deploy/update.sh` — обходы блокировок появляются
   почти каждую неделю.

На практике: YouTube и TikTok чаще всего работают без cookies, Instagram и VK
почти всегда их требуют.

## Стоимость

Платите только за OpenAI: транскрибация тарифицируется за минуты аудио
(у `whisper-1` порядка $0.006 за минуту, то есть примерно $0.36 за час видео),
конспект, ответы на вопросы и генерация теста — за токены chat-модели и на фоне
транскрибации почти незаметны (конспект и тест к тому же кэшируются). Актуальные цены
смотрите на [странице тарифов OpenAI](https://openai.com/api/pricing/).
Поэтому список `ALLOWED_USER_IDS` — не формальность.

## Структура

```
app/
  __main__.py    точка входа, логирование
  bot.py         хендлеры aiogram, превью ссылки, распознавание медиа, режим группы, очередь задач
  audio.py       площадки (YouTube/Instagram/VK/TikTok), yt-dlp, ffmpeg-перекодирование и нарезка
  transcriber.py вызовы OpenAI: расшифровка, конспект, ответы на вопросы, тест
  lesson.py      экраны интерактивного конспекта и теста, кэш в data/transcripts
  config.py      настройки из .env
  utils.py       мелкие помощники
data/
  transcripts/   кэш расшифровок, конспектов и тестов
  links/         короткие ключи ссылок для кнопок превью
  tmp/           рабочие файлы задач, чистится при старте
deploy/
  install.sh                 установка бота на Ubuntu
  install-bot-api.sh         сборка локального Bot API сервера (лимит 2000 МБ)
  update.sh                  обновление и рестарт
  transcriber-bot.service    шаблон systemd-юнита бота
  telegram-bot-api.service   шаблон systemd-юнита Bot API сервера
```

## Возможные проблемы

- **`Не найден ffmpeg`** — `sudo apt install -y ffmpeg`. Он нужен и для локальной
  отладки: без него скачивание видео с YouTube падает на склейке дорожек
  (TikTok и Instagram отдают готовый файл и работают без него).
- **В логах `Не найден JavaScript-рантайм`** — поставьте deno вручную:

```bash
curl -fsSL https://github.com/denoland/deno/releases/latest/download/deno-x86_64-unknown-linux-gnu.zip -o /tmp/deno.zip
sudo unzip -o /tmp/deno.zip -d /usr/local/bin && sudo chmod 755 /usr/local/bin/deno
```

- **`Telegram не отдаёт боту файлы больше 20 МБ`** — ограничение публичного Bot API;
  снимается локальным сервером: `sudo bash deploy/install-bot-api.sh`.
- **Локальный сервер не стартует** — `journalctl -u telegram-bot-api -n 40`. Частые
  причины: неверные `api_id`/`api_hash` в `/etc/telegram-bot-api.env` или бот не был
  разлогинен из облака (`logOut`).
- **После переключения бот молчит** — облачный `logOut` освобождает токен не мгновенно;
  подождите минуту и `sudo systemctl restart transcriber-bot`.
- **«Даже в самом низком качестве ролик весит около N МБ»** — ролик длинный, а лимит
  публичного Bot API 50 МБ: `sudo bash deploy/install-bot-api.sh`.
- **Пришло видео в 480p вместо 1080p** — так и задумано: в лимит отправки не влезло
  большее качество, точная причина написана в подписи к видео.
- **«Скачанный файл получился без картинки/звука»** — склейка дорожек не удалась;
  проверьте, что на сервере есть `ffmpeg`, и повторите.
- **«Конспект устарел, соберите его заново»** — удалён файл `.lesson.json`; нажмите
  «Интерактивный конспект» под расшифровкой ещё раз.
- **«Ссылка устарела, пришлите её заново»** — из `data/links/` пропал файл с ключом
  ссылки; просто пришлите ссылку ещё раз.
- **«Instagram/VK отдаёт это видео только авторизованным»** — нужны cookies, см.
  раздел про анонимный доступ выше.
- **«VK не отдала это видео»** — `yt-dlp` для VK часто возвращает голое `Error`
  без подробностей: проверьте ссылку в браузере и добавьте `VK_COOKIES_FILE`.
- **`OpenAI отклонил ключ API`** — ключ неверный или отозван.
- **`OpenAI вернул 429`** — закончились деньги на балансе или сработал лимит запросов.
- **Бот молчит** — смотрите `journalctl -u transcriber-bot -n 50`; при конфликте
  `TelegramConflictError` где-то запущена вторая копия бота с тем же токеном.
- **Диск кончился** — кэш расшифровок лежит в `data/transcripts`, чистится вручную:
  `find data/transcripts -mtime +30 -delete`.
